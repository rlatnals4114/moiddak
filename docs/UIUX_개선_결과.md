## 4. 보류 항목 (추가 승인 필요 / 남은 한계)

### 4-1. 실제 참석 여부 (승인 필요 — 미적용)
- **원하는 경험**: 확정 후 각 참여자의 ‘참석/불참/미정’을 보여 주기.
- **지금 안 되는 이유**: 참석을 저장하는 열·RPC 가 없다. 지금 보이는 건 ‘일정 투표 응답’뿐이라 참석으로 바꿔 보여 주면 거짓 정보가 된다.
- **현행 대안(적용함)**: ‘명단’ + 접힌 「조율 결과」 + ‘확정 시간 가능으로 응답’. 한계: 투표 후 사정이 바뀐 걸 알 수 없음.
- **변경안(초안)**: `participants` 에 `attendance text check (attendance in ('yes','no','maybe')) null` + `attendance_updated_at`, 본인만 바꾸는 `set_my_attendance(p_meeting_id, p_value)` SECURITY DEFINER RPC(확정 후에만). 기존 행은 null(미정)로 두고 백필 없음. 읽기는 기존 RLS(같은 약속 참여자) 그대로.
- **적용·검증·되돌리기**: 새 SQL 파일(007) 추가 → 사용자 SQL Editor 실행 → `tests/` 에 권한(남의 참석 변경 거부)·확정 전 거부 테스트 → 되돌리기는 열·함수 drop(데이터는 새 열에만 있음).

### 4-2. 기타 한계
- 지도 ‘사용자가 선택한 지역’: 앱에 지역 선택 기능이 없어서 **이 기기에서 그 약속 지도를 마지막으로 본 위치**(localStorage)로 대신한다. 다른 기기와 공유되지 않음.
- 캘린더 겹침은 이 화면에 불러온 범위(오늘 기준 120일 전 ~ 270일 뒤)의 **내가 볼 수 있는 모이딱 약속끼리만** 비교한다. 다른 캘린더·권한 밖 약속은 포함하지 않으며, 화면에도 그렇게 안내한다.
- 그룹 색은 모임방 id 로 계산(8색). 모임방이 많으면 같은 색이 겹칠 수 있음 → 이름 글자를 항상 함께 표시. 사용자별 색 저장은 DB 변경이 필요(미적용).
- 확정 일시는 한국 시간(일광절약시간 없음) 기준으로만 표시한다. 다른 시간대 사용자 지원은 범위 밖.
- 홈 약속 카드의 ‘n/N명 응답 완료’·회색 캐릭터는 확정 후에도 일정 응답 기준이다(홈은 지침상 검토만, 수정하지 않음).
- 실기기·사용자 테스트는 아직 하지 않음.
