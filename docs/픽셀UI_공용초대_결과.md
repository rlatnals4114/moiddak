## 1. 조사 결과(사실)
- 홈 카드의 굵은 왼쪽 선 = `.cal-item` 의 `border-left: 6px solid 모임방색`. 일회성 약속 색이 남색(#242338)이라 검은 선처럼 보였다.
- ‘캘린더 ›’·‘전체 보기 ›’ = 전역 `a` 스타일(파란 글자·밑줄). 캘린더로 가는 길은 홈 링크·하단 탭·내 정보 ‘내 캘린더’ 3곳(역할이 달라 하나도 지우지 않음).
- 실명 예시: 내 정보 닉네임 ‘예: 수민’, 모임방 멤버 추가 ‘예: 지민, 현우’.
- 모임방 초대: **멤버별 개인 토큰**(`private.group_invites`, SHA-256 해시 저장, 30일, 1회용). 기존 멤버 행 연결(claim)은 이 토큰으로만 되며 닉네임으로는 안 된다. 공용 링크는 **없었다**.
- `create_group` 은 내 이름 1개만으로도 동작 → **멤버 사전 입력 없는 생성은 DB 변경 없이 가능**.
- 가입·참여 분리: 약속 참여자는 약속을 만들 때 고른 멤버만. 모임방 멤버가 되어도 기존 약속 참여자/응답은 생기지 않는다(트리거는 '이미 참여자로 등록된 멤버 행'에만 기기를 연결).
- 속도 제한: 앱 DB 안에는 없음. 익명 로그인 자체는 Supabase 프로젝트 설정(IP당 한도)으로 제한 중.

## 3. 공용 초대 설계 — `supabase/007_group_join_link.sql` (실행됨)
- **새 표(private 스키마, API 비공개)**: `group_join_links`(해시 토큰·만료·폐기·사용 수, 모임방마다 살아 있는 링크 1개 — 부분 유일 인덱스), `group_join_attempts`(실패 기록, 사용자 id·시각만, 하루 뒤 삭제).
- **RPC**(모두 `SECURITY DEFINER` + `search_path = ''` + 스키마 명시 + `authenticated` 만 실행, 내부에서 `auth.uid()`·관리자 여부 검사 — 공용 링크 표가 private 이라 RLS 로는 접근할 수 없기 때문에 정의자 권한이 필요):
  - 관리자: `create_group_join_link`(발급=회전, 이전 공용 링크만 폐기), `revoke_group_join_link`, `group_join_link_status`(원문 없음).
  - 받는 사람: `preview_group_join_link`(이름·테마·상태만: ok/invalid/revoked/expired/archived/full/member), `join_group_with_link(token, 이름)`.
- **가입 한 트랜잭션**: 링크 행 잠금 → 모임방 잠금 → 이미 멤버면 그 멤버 반환 → 폐기·만료·종료·정원(50)·사용 한도·제외 이력·이름 중복 검사 → `member` 역할로 새 행 insert → 사용 수 +1. `(group_id, user_id)` 활성 유일 인덱스(004)로 동시 요청에도 1행, 충돌 시 기존 행 반환.
- **claim 하지 않음**: 공용 링크는 항상 새 멤버 행. 같은 이름의 기존 멤버가 있으면 ‘다른 이름으로’ 안내(기존 행·응답·권한을 가져갈 수 없음). 기존 멤버 연결은 지금처럼 개인 토큰만.
- **회전·폐기**: 이전 공용 링크만 무효, 이미 들어온 멤버·개인 초대 링크는 그대로.
- **속도 제한(DB 안)**: 같은 사용자 10분 안 실패 20회 이상이면 거부. 잘못된 토큰은 오류 대신 `invalid` 상태로 돌려줘 실패 기록이 남게 함.
- **되돌리기**: 함수 drop(+ 필요 시 링크 전부 폐기). 이미 가입한 멤버 행은 일반 멤버로 남음 — 사용자 데이터 삭제 없음.

### 방어 범위
| 지금 구조로 되는 것 | 추가 인프라가 필요한 것 |
| --- | --- |

| 사용자별 실패 횟수 제한, 정원·사용 한도, 관리자 전용 발급/회전/폐기 | IP 단위 제한·봇 탐지(Edge/Workers 쪽 별도 구현) |

### 결정이 필요한 사항
1. 정원 50명, 링크 유효 30일(최대 90일) 기본값이 괜찮은지.
2. **관리자가 뺀 사람은 공용 링크로 다시 못 들어옴**(관리자가 다시 추가 + 개인 링크) 정책이 괜찮은지.
3. 새로 가입한 멤버가 **가입 전에 만든 약속의 제목·상태·날짜**를 모임방 목록에서 보는 기존 정책(004)을 그대로 둘지(상세·응답은 지금도 참여자만).
